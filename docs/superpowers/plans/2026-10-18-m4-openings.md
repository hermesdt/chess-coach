# M4 Openings Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The owner learns and remembers a full low-theory repertoire — London (White), Caro-Kann (Black vs 1.e4), Slav set-up incl. anti-London (Black vs 1.d4/1.c4/1.Nf3) — level-aware (spec §18): validated repertoire files with a short "why" per move, a tree explorer, a line drill, opening cards in the shared review queue, and a "leaks" list built from their own games.

**Architecture:** Repertoires are JSON move trees in `content/repertoires/`. A loader turns a tree into nodes with ids and FENs. A validator script (`pnpm validate:content`) checks legality and engine soundness. Opening cards are generated from the tree into the M3 card store. Leak detection walks each synced game against the repertoire of the user's colour.

**Tech Stack:** as M1–M3. Validator runs with `tsx` and the M2 `EnginePool`.

**Spec:** `docs/superpowers/specs/2026-10-18-chess-coach-design.md` (§2.5, §2.6, §4 "Wrong content", §9 Repertoires + Validation, §10 Opening cards, §12 screen 5, §17.5)

## Global Constraints

- Repertoire file format (`content/repertoires/<id>.json`):
  ```json
  { "id": "caro-kann", "name": "Caro-Kann Defense", "color": "black",
    "moves": [ { "san": "e4", "comment": "…", "tags": ["main"], "level": 1, "children": [ … ] } ] }
  ```
  Root `moves` are the first moves of the game (White's). Node id = the SAN path joined by spaces (`"e4 c6 d4 d5"`). `level` (1–3) is optional and inherited from the parent (root default 1). Opening cards, the drill and leak detection only use nodes with `level <= currentLevel(db).level` (`server/level.ts`, built in M2).
- At a node where the repertoire side is to move there is at most ONE child (the repertoire move). Opponent nodes may have many children.
- Every repertoire-side move has a `comment` of 1–2 plain sentences (≤ 220 characters) saying *why*, in simple English for a 550-rated player. Opponent moves may have a comment (e.g. "Common at your level. It threatens …").
- Coverage and depth: spec §9 lists + §18.2. Level 1 nodes: main lines 6–8 moves deep plus the replies beginners actually play; level 2–3 nodes extend to 10–14 moves and add sidelines. Repertoires: `caro-kann` (Black, root 1.e4), `slav` (Black, roots 1.d4 / 1.c4 / 1.Nf3), `london` (White, root 1.d4 with the system d4, Bf4, e3, Nf3, c3, Bd3, Nbd2, O-O).
- Validator rules (fail the run, print node id + engine best move):
  - illegal SAN from the parent position;
  - repertoire-side move loses ≥ 15 win % vs the engine best (nodes 1 000 000, multipv 1, evaluated from the mover's view);
  - repertoire-side node with > 1 child; repertoire move without comment, or comment > 220 chars;
  - duplicate sibling SAN.
- Opening cards: one per repertoire-side node that has a child. `positionKey` dedupes transpositions (refs merged). Prompt: `"{Repertoire name}: your move."`; `solution.accepted = [child uci]`, `best` = same, `explanation` = child comment; `lastMove` = parent move UCI. New cards are introduced in depth-first line order via a new `sort_order` column; the session's new-card picker orders by `(sort_order, id)`.
- Leak: in a game where `userColor` equals the repertoire colour, the first ply where the user's move differs from the repertoire move (while still in book). "Out of book": the opponent played a move with no child. Leak positions with an existing opening card make that card due now (unless suspended).

## Review Focus

1. Transposition (same position via two move orders) → one card, two refs — test in Task 2.
2. A game that leaves book on the opponent's move is not a leak — test in Task 5.
3. Castling and promotions in SAN↔UCI (`O-O` → `e1g1`/`e8g8`) inside the tree — test in Task 1.
4. A game played as White does not get compared to the Caro-Kann (colour mismatch) — test in Task 5.
5. Editing a repertoire (a move changes) → regenerating cards updates `solution` of the affected card and suspends cards whose node no longer exists — test in Task 2.
