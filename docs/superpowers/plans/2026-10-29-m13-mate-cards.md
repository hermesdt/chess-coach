# M13 Missed-Mate Cards Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn each missed mate in 1 or 2 in the owner's games into a `mate` review card that shows the move played.

**Architecture:** A pure chess.js solver (`findMates`) proves each mate. A scanner reads stored `MoveAnalysis` rows and builds `mate` cards through `upsertCard`. Sync runs after each game analysis and once at server start. The review page treats a `mate` card like a `mistake` card (accepted list is complete, no engine check).

**Tech Stack:** TypeScript, chess.js, node:sqlite, vitest, React 19.

**Spec:** `docs/superpowers/specs/2026-10-29-m13-mate-cards-design.md` (approved by the owner).

## Global Constraints

- The AI never invents moves. A card exists only when chess.js proves the mate.
- Tests never hit the network. Tests never read `data/chess.db`. Use fixtures built in the test.
- Never delete or overwrite `data/chess.db`. Manual runs use `pnpm smoke:start` / `pnpm smoke:stop <pid>`.
- Write user-facing text (prompts, UI, roadmap, final message) in ASD-STE100 Simplified Technical English: short active sentences.
- Commit trailer: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- Work on branch `m13-mate-cards`. At the end: gates, backup, merge into `main` with `--no-ff`, push (ROADMAP rule 6).

## Review Focus

- Black owner: `evalBefore.mate` is from the mover's view; the scan must work for both colours (Task 2).
- Played move is itself a mate while the stored mate is 2: no card (Task 2).
- Promotion mates: UCI has a fifth character (Task 1).
- Same position in two games: one card, two refs (Task 3).
- Existing `mistake` card at a mate ply: its ref is dropped, a card without refs is suspended, FSRS state stays (Task 3).
- Few `mate` cards: unused quota goes to other kinds (Task 5).

**Files:**

- Test: `server/srs/mates.test.ts`

**Interfaces:**
- Produces: `findMates(fen: string): { mateIn: 1 | 2; moves: string[] } | null`. `moves` holds every legal move (UCI, promotion suffix included) that mates in `mateIn`, where `mateIn` is the shortest mate for the side to move. Null when no mate in 1 or 2 exists.

- [ ] **Step 1: Write the failing tests** (`mates.test.ts`)
  - `mate in 1`: FEN `6k1/5ppp/8/8/8/8/8/R3K3 w - - 0 1` → `{ mateIn: 1, moves: ['a1a8'] }`.
  - `mate in 2`: FEN `7k/8/8/8/8/8/1R6/R3K3 w - - 0 1` → `mateIn` 2 and `moves` contains `a1a7` and `b2b7`.
  - `no mate`: start position → `null`.
  - `prefers the shortest mate`: FEN `7k/5Q2/6K1/8/8/8/8/8 w - - 0 1` → `mateIn` 1, `moves` contains `f7g7` and `f7f8`, and does not contain `g6f6` (stalemate, not mate).
  - `black to move`: mirror the mate-in-1 FEN for Black (`r3k3/8/8/8/8/8/5PPP/6K1 b - - 0 1`) → `{ mateIn: 1, moves: ['a8a1'] }`.
  - `promotion mate`: a position where only a promotion mates in 1 returns a UCI with the fifth character (for example `7k/5P1P/6K1/8/8/8/8/8 w - - 0 1` has `f7f8q`; check the result with chess.js and fix the FEN if it is not a mate).
  - Check each FEN by hand with chess.js while writing the test. If a FEN does not give the stated result, change the FEN, not the solver.
- [ ] **Step 2: Run** `pnpm vitest run server/srs/mates.test.ts`. Expected: FAIL (module missing).
- [ ] **Step 3: Implement `findMates`** in `server/srs/mates.ts` with exhaustive chess.js search. Depth 1: moves where `isCheckmate()`. Depth 2 (only when depth 1 is empty): a move qualifies when the opponent has at least one legal reply (not stalemate) and every reply allows a mating move for us. Return mate in 1 when it exists, else mate in 2, else null.
- [ ] **Step 4: Run** the same test. Expected: PASS.
- [ ] **Step 5: Commit** `feat(mates): chess.js solver for mate in 1 and 2` (also add the spec file `docs/superpowers/specs/2026-10-29-m13-mate-cards-design.md` and this plan in this first commit).

### Task 2: Scan stored analysis for misses

**Files:**
- Create: `server/srs/mate-cards.ts`
- Test: `server/srs/mate-cards.test.ts`

**Interfaces:**
- Consumes: `findMates` (Task 1), `MoveAnalysis`, `GameAnalysis` from `shared/types.ts`.
- Produces:
  ```ts
  export interface MateMiss { ply: number; fen: string; color: Color; mateIn: 1 | 2; accepted: string[]; best: string; playedSan: string; line: string[] | null }
  export function findMateMisses(moves: MoveAnalysis[]): { misses: MateMiss[]; skipped: number }
  ```
  `best` is `bestUci` when it is in `accepted`, else `accepted[0]`. `line` is `pvSan` when `pvSan[0]` is the SAN of `best` and chess.js replays `pvSan` to checkmate in `mateIn` own moves; else null. `skipped` counts rows with a stored mate in 1 or 2 where chess.js disagreed.

- [ ] **Step 1: Write the failing tests.** A helper `move(over)` builds a `MoveAnalysis` with defaults. Cases:
  - `fastest mate played`: no miss, skipped 0.
  - `slower mate played`: stored `evalBefore.mate` 1, played a move not in the solver set → one miss, `mateIn` 1, `playedSan` kept.
  - `mate in 2 missed as Black`: `color: 'black'`, one miss, `accepted` from the solver.
  - `played move mates while stored mate is 2`: no miss (solver says mate in 1, move is in `accepted`).
  - `chess.js disagrees`: stored mate 1 on a position without a mate → no miss, `skipped` 1.
  - `not the owner's move` (`isUserMove: false`) and `evalBefore.mate` null, negative, or 3 or more → ignored, `skipped` 0.
  - `line`: set for a mate in 2 whose `pvSan` replays to mate; null when `pvSan` starts with another move.
- [ ] **Step 2: Run** `pnpm vitest run server/srs/mate-cards.test.ts`. Expected: FAIL.
- [ ] **Step 3: Implement `findMateMisses`.** Pre-filter by `isUserMove` and `evalBefore.mate` in {1, 2}. Then run `findMates(fenBefore)`. Equal `mateIn` and played UCI not in `moves` → miss. Different `mateIn` or null → `skipped`.
- [ ] **Step 4: Run** the test. Expected: PASS.
- [ ] **Step 5: Commit** `feat(mate-cards): scan stored analysis for missed mates`.

### Task 3: Build, sync and suspend cards

**Files:**
- Modify: `shared/types.ts` (`CardKind` gains `'mate'`; `solution` gains optional `mateIn?: 1 | 2` and `played?: string`)
- Modify: `server/srs/mate-cards.ts`, `server/srs/mistake-cards.ts`
- Test: `server/srs/mate-cards.test.ts`, `server/srs/mistake-cards.test.ts`

**Interfaces:**
- Consumes: `findMateMisses` (Task 2); `upsertCard`, `listCardsByRef`, `setRefs`, `setSuspended`, `positionKey` from `cards-repo`; `getAnalysis`, `ANALYSIS_VERSION` from `analysis-repo`.
- Produces:
  ```ts
  export function buildMateCards(db: DatabaseSync, analysis: GameAnalysis): { created: number; updated: number; suspended: number; skipped: number }
  export function syncMateCards(db: DatabaseSync): { games: number; created: number; skipped: number }
  ```
  `syncMateCards` runs `buildMateCards` for every `game_analysis` row with `status = 'done'` and `version = ANALYSIS_VERSION`. It is idempotent.

Card fields: kind `mate`; `positionKey(fen)`; prompt `"<White|Black> to move. You played <san> in a game. Find the mate in <N>."`; `solution: { accepted, best, explanation, mateIn, played }`; `refs: [{ gameId, ply }]`; `lastMove: null`. Explanation: `"Mate in 1: <best SAN>#."` or, when `line` is set, `"Mate in 2: <line joined by spaces>."`; otherwise `"Mate in 2 starts with <best SAN>."`.

- [ ] **Step 1: Write the failing tests** (in-memory DB helper as in `mistake-cards.test.ts`):
  - `creates one card per miss with the played move in the prompt`.
  - `a second run creates no card` (idempotent, `created` 0).
  - `two games, same position: one card with two refs`.
  - `a miss that is no longer a miss drops its ref and suspends an empty card; FSRS state stays` (re-run with changed analysis).
  - `a mistake card at a mate ply loses its ref and is suspended` (create the mistake card first with `upsertCard`).
  - `syncMateCards` covers all finished analyses at the current version and skips others.
  - In `mistake-cards.test.ts`: `buildMistakeCards makes no card at a ply that is a missed mate` (use a fixture with a blunder-class move at a mate position).
- [ ] **Step 2: Run** both test files. Expected: FAIL.
- [ ] **Step 3: Implement** `buildMateCards`, `syncMateCards`. Drop-and-suspend logic mirrors `buildMistakeCards` (refs of this game that are no longer a miss; empty → suspended). For each miss, also remove this game's ref at that ply from `mistake` cards and suspend them when empty. In `buildMistakeCards`, filter out moves for which `findMateMisses([m]).misses.length > 0` before the engine loop.
- [ ] **Step 4: Run** the two test files and `pnpm typecheck`. Expected: PASS. Typecheck shows `Record<CardKind, …>` errors in `session.ts`; leave them for Task 5 only if you commit Tasks 3 and 5 together, otherwise add `mate: 0` placeholders now.
- [ ] **Step 5: Commit** `feat(mate-cards): build, sync and suspend mate cards`.
