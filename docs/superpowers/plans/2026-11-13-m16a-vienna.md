# M16a Vienna Implementation Plan

> The main session implements task by task with TDD. No subagents (owner instruction).

**Goal:** Add the Vienna alongside London, with roughly 300 move nodes,
guide, drills and two middlegame plans.

**Architecture:** Extend the existing JSON content and group metadata. Keep
position-based opening cards; fix their presentation when repertoires overlap.

**Tech stack:** TypeScript, React, chess.js, Stockfish, SQLite, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-13-m16a-vienna-design.md`.

## Global Constraints

- No subagents, dependencies, schema migrations or quota changes.
- No live database writes from verification; back up before merge.
- All content moves replay in chess.js and pass existing engine validators.
- About 300 total move nodes; beginner-first level gates, no padding.
- One recommendation per White node; London remains available and unchanged.

## Review Focus

1. Shared initial position must accept e4 and d4 with an honest prompt.
2. FSRS state must survive adding/removing a second White repertoire.
3. London games must not become Vienna leaks; unsupported e4 replies are out of book.
4. Vienna plan groups must load, render and match only Vienna games.
5. New content must not rely on rare opponent blunders or misleading board claims.
