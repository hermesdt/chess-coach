# M5 AI Coach Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plain-language coaching for each analysed game and a weakness report across games, produced by the owner's choice of AI provider (Claude CLI, Codex CLI, opencode CLI, OpenRouter, Anthropic API), always grounded in engine facts.

**Architecture:** `server/ai/` holds a provider interface and five adapters that all take `{ system, user, jsonSchema }` and return raw text. A shared runner extracts JSON, validates it with zod, checks that every move the text mentions exists in the facts, and retries once with the error. Facts builders turn analysis rows into compact JSON. Results are cached in `ai_notes` by (subject, prompt version, analysis version, provider, model).

**Tech Stack:** as before + `zod` (v4), `zod-to-json-schema` only if zod v4's `z.toJSONSchema` is unavailable, `@anthropic-ai/sdk` (for `anthropic-api` only). OpenRouter via plain `fetch` (it is not a Claude SDK call).

**Spec:** `docs/superpowers/specs/2026-10-18-chess-coach-design.md` (§4 "AI inventing chess", §5 AI providers table, §11, §12 screens 3 and 8)

## Global Constraints

- Provider ids: `claude-cli`, `codex-cli`, `opencode-cli`, `openrouter`, `anthropic-api`. `auto` order: `claude-cli`, `codex-cli`, `anthropic-api`, `openrouter`, `opencode-cli`.
- Settings keys: `ai_provider` (`auto` | id | `none`, default `auto`), `ai_model_<id>` (optional string per provider), `openrouter_api_key` (write-only, like the lichess token; env `OPENROUTER_API_KEY`), `anthropic_api_key` (write-only; env `ANTHROPIC_API_KEY`). DTO exposes `aiProvider`, `aiModels: Record<id, string | null>`, `openrouterKeySet`, `anthropicKeySet`.
- CLI adapters: spawn without a shell (`execFile`/`spawn` with an args array), prompt via stdin when the CLI supports it, cwd = a fresh temp dir, env inherited, timeout 180 s (kill the process group on timeout), no tools/agents enabled where the CLI allows it. Before writing an adapter, run the CLI's `--help` with a 20 s timeout and `</dev/null`, and record the flags used in the adapter's header comment.
- `anthropic-api`: `@anthropic-ai/sdk`, `client.messages.parse()` with `output_config: { format: zodOutputFormat(schema), effort }`, default model `claude-opus-5-5`, effort `low`, top-level `cache_control: { type: 'ephemeral' }`, `max_tokens: 16000`; check `stop_reason` (`refusal`, `max_tokens`) before reading `parsed_output`; never send `thinking: {type: 'disabled'}` or `budget_tokens`.
- `openrouter`: `POST https://openrouter.ai/api/v1/chat/completions`, headers `Authorization: Bearer <key>`, `HTTP-Referer: http://localhost`, `X-Title: chess-coach`; body `{ model, messages: [system, user], response_format: { type: 'json_schema', json_schema: { name, strict: true, schema } } }`. Default model: an Anthropic Sonnet slug confirmed from `GET https://openrouter.ai/api/v1/models` at build time (record it in the adapter).
- Prompt text lives in `server/ai/prompts/*.ts` with `PROMPT_VERSION` constants. System prompts are fixed strings (no dates/ids) so they cache.
- Grounding rule (all outputs): any SAN-looking token in the output text (`/\b(?:[KQRBN][a-h]?[1-8]?x?[a-h][1-8]|[a-h]x[a-h][1-8]|[a-h][1-8](?:=[QRBN])?|O-O(?:-O)?)[+#]?/g`) must appear in the facts' SAN set; otherwise the runner retries once with "You mentioned moves that are not in the facts: …"; a second failure fails the call with `AiGroundingError` (shown to the user as "The coach answer mentioned moves I could not verify. Try again or use another provider.").
- Lesson ids (fixed enum, also used by M6): `blunder-check`, `free-material`, `center`, `develop`, `castle`, `trades`, `bishop-pair`, `castling-sides`, `tactics`, `mates`, `caro-kann-plans`, `london-plans`. Tag → lesson map: `hung_piece`→`blunder-check`, `missed_capture`→`free-material`, `bad_trade`→`trades`, `missed_mate`/`allowed_mate`→`mates`, `early_queen`/`slow_development`/`same_piece_twice`→`develop`, `no_castle`→`castle`. Lives in `shared/lessons.ts`.
- Writing style the prompts demand: simple English, short sentences, second person, no engine numbers, encouraging and honest, max 3 sentences per field.
- Tests never spawn real CLIs or hit the network (inject a `run` function / `fetchFn` / SDK client). One manual smoke per provider at the end, only for providers that are available.

## Review Focus

1. A CLI that prints extra text around the JSON (preamble, code fences) — the runner extracts the first top-level JSON object — test in Task 1.
2. A CLI that hangs → killed at the timeout, error surfaces as a job error, not a stuck job — test in Task 2.
3. AI returns a moment for a ply that is not a key moment → dropped silently; returns no moments → still valid — test in Task 4.
4. Switching provider shows the cached result for that provider and does not re-call others — test in Task 4.
5. Secrets: neither API key appears in any API response, log line, or job message — test in Task 1 (settings) and Task 3 (error messages redact the key).

### Task 1: AI core — interface, runner, registry, settings  *(model: sonnet)*

**Files:** Create `server/ai/types.ts`, `server/ai/runner.ts`, `server/ai/json-extract.ts`, `server/ai/grounding.ts`, `server/ai/registry.ts`, `server/routes/ai.ts`, `shared/lessons.ts`; Modify `server/config.ts`, `server/routes/settings.ts`, `shared/types.ts`, `server/app.ts`; Test `server/ai/runner.test.ts`, `server/ai/json-extract.test.ts`, `server/ai/grounding.test.ts`, `server/ai/registry.test.ts`, `server/routes/ai.test.ts`

**Interfaces — Produces:**
```ts
export type ProviderId = 'claude-cli' | 'codex-cli' | 'opencode-cli' | 'openrouter' | 'anthropic-api';
export interface AiRequest { system: string; user: string; schemaName: string; jsonSchema: object }
export interface AiProvider {
  id: ProviderId; label: string;
  available(): Promise<{ ok: boolean; reason?: string }>;
  complete(req: AiRequest, opts: { model: string | null; signal?: AbortSignal }): Promise<{ text: string; model: string }>;
}
```
- `extractJson(text: string): unknown` (strips code fences, finds the first balanced top-level `{…}`; throws `AiParseError`).
- `findUngroundedMoves(text: string, allowedSan: Set<string>): string[]` (normalises `+`/`#`).
- `runStructured<T>(provider, req, schema: ZodType<T>, opts: { model; allowedSan: Set<string>; textOf: (t: T) => string[] }): Promise<{ value: T; model: string }>` — parse → zod → grounding; one retry appending the error to `user`; throws `AiParseError` / `AiValidationError` / `AiGroundingError`.
- `createRegistry(deps: { db; run?: CliRunner; fetchFn?; anthropicClient? }): { list(): AiProvider[]; get(id): AiProvider; pick(preferred: 'auto' | ProviderId | 'none'): Promise<AiProvider | null> }` — adapters are registered by Tasks 2–3; in this task register fakes in tests.
- Routes: `GET /api/ai/providers` → `{ id, label, ok, reason, model }[]`; `POST /api/ai/providers/:id/test` → runs a tiny schema `{ ok: boolean }` prompt, returns `{ ok, model, ms }` or `{ ok: false, error }`.
- Settings additions per Global Constraints.

- [ ] Step 1: failing tests — `extractJson('Sure!\n```json\n{"a":1}\n```')` → `{a:1}`; nested braces inside strings handled; `findUngroundedMoves('Play Nf3 then e4', new Set(['Nf3']))` → `['e4']`; runner retries once then succeeds; grounding failure twice → `AiGroundingError`; `pick('auto')` returns the first available in the fixed order; settings PUT `openrouterApiKey` → GET shows `openrouterKeySet: true` and the key text is absent from every response body.

### Task 2: CLI adapters (claude, codex, opencode)  *(model: sonnet)*

**Files:** Create `server/ai/cli-runner.ts`, `server/ai/providers/claude-cli.ts`, `server/ai/providers/codex-cli.ts`, `server/ai/providers/opencode-cli.ts`; Modify `server/ai/registry.ts`; Test `server/ai/cli-runner.test.ts`, `server/ai/providers/cli-adapters.test.ts`

**Interfaces — Produces:** `type CliRunner = (cmd: string, args: string[], opts: { stdin?: string; timeoutMs: number; cwd: string }) => Promise<{ code: number | null; stdout: string; stderr: string; timedOut: boolean }>`; `realCliRunner: CliRunner` (spawn, detached process group, kill on timeout); one adapter per CLI.
- claude-cli: `claude -p --output-format json` (+ `--model <m>` when set; add the flags that disable tools if `claude --help` lists them, e.g. `--tools ""`/`--disallowedTools`, and `--json-schema` if available); stdin = system + user; output JSON's `result` field is the text; `is_error: true` → error.
- codex-cli: `codex exec` with `--skip-git-repo-check`, read-only sandbox, `--output-schema <tmpfile>` and `--output-last-message <tmpfile>` if `codex exec --help` lists them (otherwise rely on the prompt + JSON extraction); `-m <model>` when set; read the last-message file as text. If `codex exec --help` hangs or the binary is unusable non-interactively, mark the adapter unavailable with that reason (and report it) instead of guessing.
- opencode-cli: `opencode run --format json` (+ `-m provider/model` when set); parse the JSON event stream and concatenate the assistant text parts of the final message.
- `available()`: binary resolves on PATH (`which` equivalent via `execFile` with 5 s timeout).
