# M12b Coach Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement the tasks below, using test-first cycles.

**Goal:** Ground the coach's middlegame advice in the current board and matching authored plans.

**Architecture:** Compute position structure using chess.js and match plan triggers at the chat anchor. Add matched plans to the fact pack, validate selected plan IDs and explicit file claims through the existing retry flow, and surface selected plans as links in chat while accepting saved older answers.

**Tech Stack:** TypeScript, chess.js, Zod, React, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-29-middlegame-plans-design.md`, section 8.

## Global Constraints

- Moves must come from engine or game facts, never plan text alone.
- No network in tests; no writes to the owner's database for smoke tests.
- Preserve existing saved chats and avoid a database migration.

## Review Focus

- Both sides' legal pawn breaks must respect checks and en passant rights.
- File status and pawn structure must be relative to the correct color.
- Existing stored chat answers and fact packs must remain readable.
- Unknown plan IDs and false file claims must trigger the existing retry.
- Plan text must not accidentally authorize ungrounded chess moves.
