# M6 Principles Course Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Twelve short lessons that teach the beginner principles the owner asked for ("two bishops are strong", "taking is not always good", "go for the centre", "castle where they castle — or not", "develop fast"), each with validated interactive exercises that join the review queue after the lesson is done.

**Architecture:** Lessons are JSON files in `content/lessons/` (body in a small Markdown subset + exercises). The M4 validator is extended to lessons. A course API serves lessons and progress; completing a lesson creates `lesson` cards in the M3 store. Tag → lesson links (from `shared/lessons.ts`, created in M5) appear on the dashboard, review screen and coach report.

**Tech Stack:** as before + `react-markdown` for lesson bodies.

**Spec:** `docs/superpowers/specs/2026-10-18-chess-coach-design.md` (§1, §2.7, §4 "Wrong content", §9 Lessons + Validation, §10 Lesson cards, §12 screen 6, §17.5)

## Global Constraints

- Lesson ids and order are fixed (from `shared/lessons.ts`): 1 `blunder-check`, 2 `free-material`, 3 `center`, 4 `develop`, 5 `castle`, 6 `trades`, 7 `bishop-pair`, 8 `castling-sides`, 9 `tactics`, 10 `mates`, 11 `caro-kann-plans`, 12 `london-plans`. Lesson 11 covers Caro-Kann and Slav plans together (same structure family, spec §18.2). Titles and topics as spec §9 "Ordered course".
- File `content/lessons/<nn>-<id>.json`: `{ id, order, level: 1, title, summary (≤ 140 chars), tags: Tag[], body: string, exercises: Exercise[], links: { title, url }[] }` (all M6 lessons are level 1; level 2–3 lessons come in M8 and are locked until `currentLevel` reaches them); `Exercise = { id, fen, prompt, solution: string[] (UCI), explanation }`.
- Body: 150–400 words, Markdown subset only (paragraphs, `**bold**`, `-` lists, `###` headings). Simple English, short sentences, second person. At least one "Rule of thumb:" line. Lesson 8 must explain when "castle on the same side as your opponent" is good advice and when opposite-side castling with a pawn storm is better.
- 3–6 exercises per lesson. `prompt` starts with "White to move." or "Black to move." matching the FEN side to move.
- Validator additions (fail the run): invalid FEN; prompt side ≠ FEN side; solution move illegal; any solution move loses ≥ 10 win % vs engine best (nodes 1 000 000); duplicate exercise ids; body word count outside 150–400; missing "Rule of thumb:".
- `links` start empty (the owner adds YouTube links by hand later). No made-up URLs.
- Lesson cards: one per exercise after the lesson is completed; `positionKey` from the FEN; prompt = exercise prompt; `solution.accepted` = `solution`; `best` = engine best if it is in `solution`, else `solution[0]`; `explanation` = exercise explanation; refs `{ lessonId, exerciseId }`.

## Review Focus

1. Exercise whose position is already lost or trivially won (any move wins) — the validator warns when the best move's win % gain over the second-best move is < 5 (exercise teaches nothing) — test in Task 1.
2. Completing a lesson twice does not duplicate cards — test in Task 1.
3. A lesson file edited after completion (exercise changed) → card solution updates on next startup — test in Task 1.
4. Lesson page on a narrow window: board and text stack vertically — checked in Task 2 screenshot.
5. Tag → lesson link for a tag with no lesson (none today; keep the map total) — test in Task 2 that every `Tag` maps to a lesson id.
