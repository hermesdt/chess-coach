# M17 Play-it-out Cards Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> Project rule (owner, 2026-11-10): the main session implements this plan itself. No subagents.

**Goal:** A `playout` card kind: the owner plays 5 moves from a middlegame position against Stockfish, with live tag feedback, "show, then rewind" on blunders, fewer new opening cards, and a blunders-per-game chart.

**Architecture:** Cards are built from stored game analysis (no engine) and from repertoire leaf positions (engine check, background job). A stateless endpoint judges one owner move at a time with the existing engine pool, cache, `classify` and `materialTags`, and returns Stockfish's reply. A new React component drives the board like `MateLine`; the review page rates the card from the result.

**Tech Stack:** TypeScript, Hono, node:sqlite, chess.js, Stockfish via `EnginePool`, React, react-chessboard, Vitest + Testing Library.

**Spec:** `docs/superpowers/specs/2026-11-22-m17-play-it-out-design.md`

## Global Constraints

- Moves come only from Stockfish, chess.js or validated `content/`. Feedback text is fixed templates filled with chess.js/engine data; no AI text.
- Tests never hit the network or a real Stockfish; use fake pools (`{ analyse: async (fen, opts) => lines }`) as in `server/routes/review-check.test.ts`.
- 5 kept owner moves per card. Stockfish replies with its best move (`pv[0]`).
- Blunder = `classify(...) === 'blunder'` (win % loss ≥ 30). Only blunders rewind; mistakes and inaccuracies warn and continue.
- Playable start: owner win % 25–75 inclusive.
- Rating: Good = 0 rewinds and end win % ≥ start − 10; Hard = 1 rewind, or 0 rewinds and end < start − 10; Again = ≥ 2 rewinds.
- Verdict band: end − start > 10 "Better", < −10 "Worse", else "About the same".
- Hint arrow (Stockfish best move) after the second rewind at the same position.
- Engine budget per search: `CHECK_NODES` (200 000), multipv 1, through `EngineCache`.
- Level mix (shares, multiples of 0.05): L1 mistake .15 mate .1 threat .1 lesson .2 plan .1 opening .05 playout .3; L2 .15/.1/.1/.2/.1/.15/.2; L3 .1/.1/.1/.15/.15/.25/.15.
- Work in worktree `.worktrees/m17` on branch `m17-play-it-out` (the owner's `tsx watch` restarts on changes in the main checkout).
- Before the merge (it adds a migration): `sqlite3 data/chess.db ".backup data/backups/pre-m17-<date>.db"`. Never touch `data/chess.db` otherwise. Smoke runs use `pnpm smoke:start` / `pnpm smoke:stop <pid>`.
- User-facing copy in plain short sentences (STE style).

## Review Focus

1. A promotion move (5-char UCI) by the owner or as Stockfish's reply: the step must play it and return the right SAN. → Task 3 test.
2. Stockfish's reply mates the owner, or the owner's move mates/stalemates: the card ends at once and still rates from rewinds. → Tasks 3 and 4 tests.
3. A second board move while a step request is pending: it is ignored, not sent. → Task 4 test.
4. The engine fails during a step (rejects): the endpoint answers 502; the board shows "The engine check is not available." and offers Skip, as other cards do. → Tasks 3 and 4 tests.
5. A step request with a FEN where the owner is not to move, or an illegal move: 400, no engine call. → Task 3 test.

**Files:**

**Interfaces:**
- Consumes: `classify`, `winPct`, `moverWinAfter`, `flip` (`server/analysis/winpct.ts`); `materialTags`, `playUci`, `PIECE_VALUE` (`server/analysis/tags-material.ts`).
- Produces:
  - `analyseCached(fen: string, pool: Pick<EnginePool,'analyse'>, cache: EngineCache | undefined, nodes = CHECK_NODES): Promise<EngineLines>` (same cache rules as today's `winAfter`).
  - `shared/types.ts`:
    ```ts
    export interface PlayoutStep {
      san: string; fenAfter: string; classification: Classification; tags: Tag[];
      winBefore: number; winAfter: number; bestUci: string | null; bestSan: string | null;
      reply: { uci: string; san: string; fen: string } | null; gameOver: boolean; feedback: string | null;
    }
    ```
  - `playoutStep(fen: string, uci: string, pool, cache?): Promise<PlayoutStep>` — throws `PlayoutInputError` for an illegal move or bad FEN.
  - `playoutFeedback(input: { fenBefore: string; uci: string; classification: Classification; tags: Tag[]; bestUci: string | null; reply: { uci: string; san: string } | null; winLoss: number }): string | null`
  - Route `POST /api/review/cards/:id/playout-step` body `{ fen, uci }` → 200 `PlayoutStep`; 404 unknown card; 400 not a playout card, bad body, side to move ≠ `card.sideToMove`, or illegal move; 502 `{ error: 'engine' }` when the engine rejects.
  - `api.playoutStep(cardId: number, fen: string, uci: string): Promise<PlayoutStep>`

Behaviour of `playoutStep`: search `fen` (before); play the move; if checkmate → `winAfter 100`, `reply null`, `gameOver true`, no second search; if other game over → `winAfter 50`, `gameOver true`. Else search `fenAfter`; `winBefore = winPct(before[0].score)`, `winAfter = moverWinAfter(after[0].score)`, `isBest = before[0].pv[0] === uci`; tags from `materialTags` with `evalBeforeMover = before[0].score`, `evalAfterMover = flip(after[0].score)`; reply = `after[0].pv[0]` played with chess.js (null if the pv is empty); `gameOver` true when the position after the reply is game over.

Feedback (only for blunder, mistake, inaccuracy; else null). First matching tag wins, in this order:

| Tag | Text |
|-----|------|
| `allowed_mate` | `This move allows mate. ${reply.san} starts it.` |
| `hung_piece` | `Your ${pieceName} on ${reply.to} was undefended. ${reply.san} takes it.` (piece = captured by the reply) |
| `missed_capture` | `You could take the ${pieceName} on ${best.to}: ${bestSan}.` |
| `missed_mate` | `You had a mate: ${bestSan}.` |
| `bad_trade` | `This trade loses material. Count the pieces before you take.` |
| none | `This move loses ${Math.round(winLoss)} % of your winning chances. Stockfish prefers ${bestSan}.` |

Piece names: `p pawn, n knight, b bishop, r rook, q queen`.

**Interfaces:**
- Consumes: `api.playoutStep`, `PlayoutStep` (Task 3); `DrillBoard` props `fen, orientation, lastMove, onMove, arrows, locked`.
- Produces:
  - `PLAYOUT_MOVES = 5`
  - `playoutRating(r: { rewinds: number; startWin: number; endWin: number }): Rating`
  - `playoutVerdict(startWin: number, endWin: number): 'Better' | 'About the same' | 'Worse'`
  - `PlayoutResult = { firstUci: string; rewinds: number; warnings: number; startWin: number; endWin: number }`
  - `<PlayoutBoard card={CardWithState} onDone={(r: PlayoutResult) => void} />`

Board behaviour:
- On a move (ignored while a request is pending): call `api.playoutStep(card.id, fen, uci)`. `startWin` = the first step's `winBefore`.
- **Blunder:** show `fenAfter`, then after 600 ms the reply position; show `feedback` and a **Try again** button. It returns the board to the position before the blunder. Rewinds at this position +1, total rewinds +1. When rewinds at this position reach 2, show an arrow for `bestUci`. A blunder is not a kept move.
- **Mistake / inaccuracy:** keep; warnings +1; show `feedback` as a warning; play the reply after 600 ms.
- **Other:** keep; play the reply after 600 ms.
- **End** when kept moves = 5, `gameOver`, or `reply` is null: `endWin` = last kept step's `winAfter`; show "Start: X %. End: Y %. {verdict}." and "Rewinds: n. Warnings: m."; call `onDone`.
- **Engine error:** show `The engine check is not available.`; the review page offers Skip as it does for other errors.
- Review page: `setAnswer({ cardId, uci: r.firstUci, correct: r.rewinds === 0, rating: playoutRating(r) })`; the owner can change the rating as with other cards.
